# Security round — can each finding be reached in the unified app? (2026-10-27)

Run from `apps/unified` on `engine` @ 525f47a: `bun audit --prod` → **20 vulnerabilities at high or above (1 critical,
19 high)**, plus 40-odd moderate/low. (The brief said 34; the engine has since moved — hono, qs, form-data and
react-router were already bumped in places. This is today's list, run by me.) Note `bun audit` reads the root `bun.lock`,
so it also lists packages that only the other workspaces (platform, mobile, api) pull in; those are marked "other workspace".

"Reachable" means an attacker, or one of our own users, can get data into the vulnerable code path in a running customer app.

## What this means for order of work
1. maplibre (critical, the only critical): fix. 2. patch/minor updates in range. 3. majors one at a time —
zod (reachable DoS), nodemailer, csv-parse, react-router (the one real redirect; also closable by validating
`returnTo`), then drizzle last. The `returnTo` guard is a code change independent of the upgrade and is cheap to add.
