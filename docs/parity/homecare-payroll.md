## Gaps and uncertainty

- AxisCare: help.axiscare.com not fetchable. Overtime rules, travel, mileage and ADP/Paychex/Gusto file formats are not found in AxisCare material. Its tip sheet only says travel time must be accounted for.
- AlayaCare: travel time, mileage, double time and named ADP/Paychex/Gusto exports not found.
- WellSky Personal Care: no first-party payroll page found; the travel, mileage and export statements come from a third-party blog (hedged) and a Netchex page. Netchex page does not confirm overtime or travel transfer.
- ADP: no ADP-authored column spec was fetched; the layout above is consistent across three vendors but column D differs (Temp Dept vs Employee Name) and mileage/expense codes (EXP, MIL, HOL) are CareSmartz360 conventions, not ADP rules. Treat the ADP file as needing a live ADP sandbox test.
- ADP's separate Payroll Data Input API (protected PDF) was not opened.
- Paychex SPI: the spec sheet did not state which fields beyond A, B, E are required; it also did not say CSV vs fixed-width (the overview says .csv).
- Gusto: no named home care leader exports to Gusto; the employee-hours column headers were not published (a second Gusto page did not mention the workweeks column, so verify). Contractor CSV headers exist but are out of scope.
- Federal weekly 40-hour rule is only implied by threshold examples; no leader page describes it by name. State rules beyond California not found.
- Paid-travel calculation formula between visits (e.g. which gaps count, rounding) is not published by any leader.

## Status summary

- Built (hidden behind `care_payroll_rules`, not ready): overtime by the agency's own rule (federal, California, Alaska, Colorado), paid travel between visits at different clients, an ADP paydata file, a Paychex hours file, a payroll id for each caregiver, and a Gusto hours file that adds a double overtime column when needed. The pay run, approval, CSV, QuickBooks file and client margin report all use the same rule. 17 tests are written in `tests/homecare-depth-payroll.test.ts` (they were not run while writing this page). An agency without the feature is paid exactly as before.
- Never tested against the real products: no file has been imported into ADP, Paychex or Gusto, and ADP's layout comes from three other vendors' pages, not an ADP-written spec. The Paychex pay component names are agency settings and unconfirmed. The Gusto column names are unconfirmed.
- Left unbuilt: a live push to any payroll provider (each needs that provider's sandbox account), the Gusto workweeks column, mileage in the ADP and Paychex files, Nevada and other state rules, blended regular rate, meal and rest break premiums, holiday pay, overnight splitting at midnight, per-pay-code overtime exclusion, warn-or-block limits, and address-based travel and mileage. The rate and break-pay rules need the owner's payroll adviser to decide them first. Pay periods are read as whole work weeks.
- The ADP file is saved under the name the server gives it (EPI + company code + two digits), which ADP needs unchanged. That is a screen step with no test; check the saved name on the first real download.
- The owner must verify by hand: upload one real hours file each to ADP, Paychex and Gusto on a test payroll before relying on any of them, and have the payroll adviser check the California, Alaska and Colorado rules against a real week of pay. Also check that paid travel is meant to be paid at the base rate.
